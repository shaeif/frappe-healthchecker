# AMC Tracker – Troubleshooting

`S` = your site name (e.g. `amc.localhost`). Prefix commands with `docker compose exec backend`.

## Scheduler disabled / daily job never runs

Symptoms: no new rows in AMC Notification Log after 08:00, *AMC Settings > Run Daily Job Now* works but cron does not.

```bash
docker compose exec backend bench --site $S scheduler status      # must say "enabled"
docker compose exec backend bench --site $S scheduler enable
docker compose exec backend bench --site $S scheduler resume       # if it was paused
docker compose exec backend bench --site $S doctor                 # "Workers online: 2"
docker compose ps scheduler queue-short queue-long                  # all "Up"
docker compose logs --tail=100 scheduler
```
* The setup wizard and `bench restore` can leave the scheduler disabled. Re-enable it after either.
* Check `sites/common_site_config.json` / `site_config.json` for `"pause_scheduler": 1` (remove it) and for
  `"maintenance_mode": 1` (`bench --site $S set-maintenance-mode off`).
* Check the job exists: **Scheduled Job Type** list → `amc_tracker.notifications.scheduler.run_daily`, Cron
  `0 8 * * *`, not *Stopped*. If missing, run `bench --site $S migrate` (cron hooks are synced on migrate).
* Wrong hour? Cron uses **System Settings > Time Zone**. It must be `Asia/Qatar`:
  `bench --site $S execute amc_tracker.setup.install.set_system_time_zone`.
* Job errors land in **Error Log** (title "AMC Tracker: …") and **Scheduled Job Log**.

## Emails stuck in Email Queue (status Not Sent / Error)

```bash
docker compose exec backend bench --site $S execute frappe.email.queue.flush   # try sending now
docker compose logs --tail=200 queue-short queue-long
```
Open **Email Queue → the email → Error** and match the message:

| Error | Fix |
|---|---|
| `Please setup default outgoing Email Account` (also logged in AMC Notification Log as *Failed*) | Create the Office 365 Email Account with **Enable Outgoing** + **Default Outgoing** (README §6). |
| `535 5.7.139 Authentication unsuccessful, SmtpClientAuthentication is disabled` | Enable *Authenticated SMTP* for the mailbox in Microsoft 365 admin, or switch the Email Account to **OAuth**. |
| `535 5.7.139 … basic authentication is disabled` | The tenant blocks Basic auth → use **OAuth** (Connected App, README §6). |
| `554 5.2.252 SendAsDenied` | Tick *Always use this email address as sender address*, or grant *Send As* on the mailbox. |
| `Connection unexpectedly closed` / timeout | Port **587** + **Use TLS** (not SSL); outbound 587 must be open from the Docker host. |
| Stays *Not Sent* with no error | Workers are down or the scheduler is disabled (the queue is flushed by a scheduled job). See above. |

Muted emails: if `mute_emails` is set in site config, nothing is sent: `bench --site $S set-config mute_emails 0`.
Resend failed ones: Email Queue list → select → *Actions > Retry sending*. AMC Notification Log rows marked *Failed*
are retried automatically on the next daily run.

## apps.txt missing the app / "No module named amc_tracker" / "App amc_tracker not installed"

```bash
docker compose exec backend cat sites/apps.txt                 # must list frappe, erpnext, amc_tracker
docker compose exec backend ls apps                            # amc_tracker present?
docker compose exec backend env/bin/python -c "import amc_tracker; print(amc_tracker.__version__)"
docker compose exec backend bench --site $S list-apps          # amc_tracker installed on the site?
```
* `sites/apps.txt` is regenerated by the **configurator** service (`ls -1 apps > sites/apps.txt`). Re-run it:
  `docker compose up -d --force-recreate configurator`, then restart:
  `docker compose restart backend queue-short queue-long scheduler websocket`.
* `import amc_tracker` fails: the containers run an old image. `docker compose build && docker compose up -d`
  (check `CUSTOM_IMAGE` / `CUSTOM_TAG` in `.env` and `docker compose images`).
* Installed in the image but not on the site:
  `docker compose exec backend bench --site $S install-app amc_tracker && docker compose exec backend bench --site $S migrate`.

## Assets not loading (unstyled pages, 404 on /assets/…, pop-ups never appear)

```bash
curl -I http://$S:8080/assets/amc_tracker/js/amc_tracker_popup.js          # expect 200
docker compose exec frontend ls -la /home/frappe/frappe-bench/sites/assets   # symlink -> /home/frappe/frappe-bench/assets
docker compose exec frontend ls -la /home/frappe/frappe-bench/assets/amc_tracker   # -> apps/amc_tracker/amc_tracker/public
```
* Assets come from the **image**. The entrypoint links `sites/assets` to the baked `/home/frappe/frappe-bench/assets`.
  After a rebuild, **recreate** the containers (`docker compose up -d` or `docker compose up -d --force-recreate`).
  A restart is not enough.
* **Never run `bench build` inside a running container**. It writes a new `assets.json` that does not match the
  image and breaks the UI. If you did, run `docker compose up -d --force-recreate`.
* `amc_tracker` assets missing: the Dockerfile's `ln -sfn … assets/amc_tracker` step did not run. Rebuild with
  `docker compose build --no-cache`.
* Browser cache: hard refresh (Ctrl+Shift+R), then `bench --site $S clear-cache` and `bench --site $S clear-website-cache`.

## Real-time pop-ups do not appear ("Invalid origin" / "Unauthorized: fetch failed" in the browser console)

* The browser must use **the same hostname as `SITE_NAME`** (nginx sets the socket Origin to `http://SITE_NAME`).
  Use `http://amc.localhost:8080`, not `http://localhost:8080` or the server IP. In production, set `SITE_NAME` to
  the FQDN and browse to it.
* No DNS name, only an IP? Set `SITE_NAME` to the IP, `HOST_NAME=http://<IP>` and `HTTP_PORT=80` before the site is
  created. The port must be 80: the websocket call-back below goes to `http://<IP>` on the host, and the network
  alias cannot redirect an IP.
* The websocket service authenticates by calling `http://SITE_NAME/api/...`. In this compose file the frontend
  has a network alias equal to `SITE_NAME` and listens on port 80 internally for that reason. Test it:
  `docker compose exec websocket node -e "fetch('http://$S/api/method/ping').then(r=>r.text()).then(console.log)"`
  should print `{"message":"pong"}`.
* Behind HTTPS (`https://FQDN`) the websocket container must resolve and reach `https://FQDN` (public DNS/hairpin NAT).
* Missed pop-ups are always under the **bell** (Notification Log). Check *AMC Settings > Enable Pop-up Notifications*
  and the rule's *Also Show Pop-up*.

## Containers do not start: "the docker-default profile could not be loaded" (AppArmor)

Docker inside a Proxmox LXC (or another container) often cannot load AppArmor profiles:
`apparmor_parser: Access denied. You need policy admin privileges to manage profiles.`
Either allow AppArmor management for the container on the host, or run the stack unconfined:

```bash
cp docker-compose.apparmor.yml docker-compose.override.yml   # git-ignored, loaded automatically
./scripts/install.sh   # or: docker compose up -d
```

## Other common issues

| Symptom | Fix |
|---|---|
| `create-site` exits with *Access denied for user 'root'* | `DB_ROOT_PASSWORD` changed after the DB volume was created. Use the original password, or `docker compose down -v` (**deletes all data**) and start again. |
| Site opens the setup wizard | `./scripts/install.sh` completes it for you; otherwise complete it in the browser (the time zone is reset to Asia/Qatar afterwards). |
| `bench migrate` did not pick up a JSON change | Bump `"modified"` in the changed JSON file, then migrate again. |
| Teams rule *Failed: HTTP 400* | The webhook URL is wrong or truncated (must be the full Workflows URL). Use *Settings > Test > Send Test Teams Card*. |
| Teams rule *Failed: No Teams webhook URL configured* | Fill *Settings > Default Teams Webhook URL* or the rule's *Teams Webhook URL*. |
| A rule never fires for an AMC | Open the AMC's **Notifications** tab: each rule shows why (cycle status filter, no recipients, no visit date, paused…). Use **Test Rules** on the rule set. Only **Active** AMCs before their *Contract End* are processed. |
| Port 8080 already in use | Change `HTTP_PORT` in `.env` (and `HOST_NAME`), then `docker compose up -d`. |
| Daily job returns `"skipped": "non-working day"` | Today is a weekend day (*Settings > Weekend Days*, default Friday, Saturday) or a **Public Holiday**. Intended: reminders are caught up on the next working day. Untick *Skip Weekends and Holidays* to send every day. |
| A reminder arrived a day earlier / later than its *Days* | Its planned date fell on a weekend or holiday and was moved ("before" reminders to the previous working day, all others to the next). The Notifications tab shows "(moved to working day)". |
| No reminders for an AMC that is due | *Reminders Paused Until* is set (directly or by a contact log entry). Clear it; rules with *Ignore Pause* (overdue escalation) still fire. |
| **Assign Engineers** button missing | Only the helpdesk, Technical Managers and System Managers assign engineers, and only on **Active** AMCs. Save the AMC first. |
| "… does not have the role AMC Engineer" when assigning | Give the user the role (*Settings > Users > Roles*), then assign again. |
| Engineer cannot set the visit date / "Engineers can only plan and report their visit" | Engineers edit only **their own** visits, and only the date, mode, times, report and findings. Reassigning the engineer is a helpdesk action. |
| Visit date refused with "… is on leave" / "… already has a PM visit" | *Settings > Block Unavailable Visit Dates* is on. Pick another date, or fix the Engineer Leave. With the setting off you only get a warning. |
| "Cycle … already has PM visits" when changing the Next PM Due Date | Moving the due date would move the cycle and orphan its visits. Sign the cycle off, or cancel its visits, first. |
| **Sign Off Cycle** says "Reports are missing for …" | Every visit (except cancelled ones) needs a Visit Report, or *Included in the combined AMC report* ticked **and** the Combined PM Report attached on the AMC. |
| Combined report attached but a visit is still *Completed* | Tick *Included in the combined AMC report* on that visit and save it. |
| *Email Client to Schedule*: "Enter the client email address." | Fill the **Client**'s contact email (and CC emails). The mail goes through the Email Queue. |
| No **Import** button on the Client / AMC list | Only users who can create the record **and** Data Import see it. Install / migrate grants Data Import to **AMC Technical Manager**. |
| AMC import: engineers missing | Use the AMC template: one row per extra engineer with only *Engineer (Engineers)* / *Expertise (Engineers)* filled. The client code must exist first (import Clients before AMCs). |
| "You don't have access to Report: AMC Management Summary / AMC Audit Trail" | Intended: the summary is for Technical / Account Managers, the audit trail for Technical Managers. |
| Dashboard charts show "No data yet" | They count signed-off cycles and reported visits. A new site shows bars after the first sign-off. |
| Desk is still in English for an Arabic user | Set *My Settings > Language* = Arabic and reload; after an upgrade run `bench --site $S clear-cache`. |
| No PM to-do email | *Settings > Send Daily PM To-Do* is off, it is a non-working day, there was nothing to list, or no enabled user has role AMC Helpdesk. *Send PM To-Do Now* sends it on demand. |
| No management summary | Weekly is sent on **Sunday** (previous 7 days), Monthly on the **1st**. Technical Managers always receive it. *Send Management Summary Now* sends it on demand. |
