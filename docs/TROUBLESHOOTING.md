# HC Tracker – Troubleshooting

`S` = your site name (e.g. `hc.localhost`). Prefix commands with `docker compose exec backend`.

## Scheduler disabled / daily job never runs

Symptoms: no new rows in HC Notification Log after 08:00, *HC Settings > Run Daily Job Now* works but cron does not.

```bash
docker compose exec backend bench --site $S scheduler status      # must say "enabled"
docker compose exec backend bench --site $S scheduler enable
docker compose exec backend bench --site $S scheduler resume       # if it was paused
docker compose exec backend bench --site $S doctor                 # "Workers online: 2"
docker compose ps scheduler queue-short queue-long                  # all "Up"
docker compose logs --tail=100 scheduler
```
* The setup wizard and `bench restore` can leave the scheduler disabled. Re-enable it after either.
* Check `sites/common_site_config.json` / `site_config.json` for `"pause_scheduler": 1` (remove it) and for
  `"maintenance_mode": 1` (`bench --site $S set-maintenance-mode off`).
* Check the job exists: **Scheduled Job Type** list → `hc_tracker.notifications.scheduler.run_daily`, Cron
  `0 8 * * *`, not *Stopped*. If missing, run `bench --site $S migrate` (cron hooks are synced on migrate).
* Wrong hour? Cron uses **System Settings > Time Zone**. It must be `Asia/Qatar`:
  `bench --site $S execute hc_tracker.setup.install.set_system_time_zone`.
* Job errors land in **Error Log** (title "HC Tracker: …") and **Scheduled Job Log**.

## Emails stuck in Email Queue (status Not Sent / Error)

```bash
docker compose exec backend bench --site $S execute frappe.email.queue.flush   # try sending now
docker compose logs --tail=200 queue-short queue-long
```
Open **Email Queue → the email → Error** and match the message:

| Error | Fix |
|---|---|
| `Please setup default outgoing Email Account` (also logged in HC Notification Log as *Failed*) | Create the Office 365 Email Account with **Enable Outgoing** + **Default Outgoing** (README §6). |
| `535 5.7.139 Authentication unsuccessful, SmtpClientAuthentication is disabled` | Enable *Authenticated SMTP* for the mailbox in Microsoft 365 admin, or switch the Email Account to **OAuth**. |
| `535 5.7.139 … basic authentication is disabled` | The tenant blocks Basic auth → use **OAuth** (Connected App, README §6). |
| `554 5.2.252 SendAsDenied` | Tick *Always use this email address as sender address*, or grant *Send As* on the mailbox. |
| `Connection unexpectedly closed` / timeout | Port **587** + **Use TLS** (not SSL); outbound 587 must be open from the Docker host. |
| Stays *Not Sent* with no error | Workers are down or the scheduler is disabled (the queue is flushed by a scheduled job). See above. |

Muted emails: if `mute_emails` is set in site config, nothing is sent: `bench --site $S set-config mute_emails 0`.
Resend failed ones: Email Queue list → select → *Actions > Retry sending*. HC Notification Log rows marked *Failed*
are retried automatically on the next daily run.

## apps.txt missing the app / "No module named hc_tracker" / "App hc_tracker not installed"

```bash
docker compose exec backend cat sites/apps.txt                 # must list frappe, erpnext, hc_tracker
docker compose exec backend ls apps                            # hc_tracker present?
docker compose exec backend env/bin/python -c "import hc_tracker; print(hc_tracker.__version__)"
docker compose exec backend bench --site $S list-apps          # hc_tracker installed on the site?
```
* `sites/apps.txt` is regenerated by the **configurator** service (`ls -1 apps > sites/apps.txt`). Re-run it:
  `docker compose up -d --force-recreate configurator`, then restart:
  `docker compose restart backend queue-short queue-long scheduler websocket`.
* `import hc_tracker` fails: the containers run an old image. `docker compose build && docker compose up -d`
  (check `CUSTOM_IMAGE` / `CUSTOM_TAG` in `.env` and `docker compose images`).
* Installed in the image but not on the site:
  `docker compose exec backend bench --site $S install-app hc_tracker && docker compose exec backend bench --site $S migrate`.

## Assets not loading (unstyled pages, 404 on /assets/…, pop-ups never appear)

```bash
curl -I http://$S:8080/assets/hc_tracker/js/hc_tracker_popup.js          # expect 200
docker compose exec frontend ls -la /home/frappe/frappe-bench/sites/assets   # symlink -> /home/frappe/frappe-bench/assets
docker compose exec frontend ls -la /home/frappe/frappe-bench/assets/hc_tracker   # -> apps/hc_tracker/hc_tracker/public
```
* Assets come from the **image**. The entrypoint links `sites/assets` to the baked `/home/frappe/frappe-bench/assets`.
  After a rebuild, **recreate** the containers (`docker compose up -d` or `docker compose up -d --force-recreate`).
  A restart is not enough.
* **Never run `bench build` inside a running container**. It writes a new `assets.json` that does not match the
  image and breaks the UI. If you did, run `docker compose up -d --force-recreate`.
* `hc_tracker` assets missing: the Dockerfile's `ln -sfn … assets/hc_tracker` step did not run. Rebuild with
  `docker compose build --no-cache`.
* Browser cache: hard refresh (Ctrl+Shift+R), then `bench --site $S clear-cache` and `bench --site $S clear-website-cache`.

## Real-time pop-ups do not appear ("Invalid origin" / "Unauthorized: fetch failed" in the browser console)

* The browser must use **the same hostname as `SITE_NAME`** (nginx sets the socket Origin to `http://SITE_NAME`).
  Use `http://hc.localhost:8080`, not `http://localhost:8080` or the server IP. In production, set `SITE_NAME` to
  the FQDN and browse to it.
* The websocket service authenticates by calling `http://SITE_NAME/api/...`. In this compose file the frontend
  has a network alias equal to `SITE_NAME` and listens on port 80 internally for that reason. Test it:
  `docker compose exec websocket node -e "fetch('http://$S/api/method/ping').then(r=>r.text()).then(console.log)"`
  should print `{"message":"pong"}`.
* Behind HTTPS (`https://FQDN`) the websocket container must resolve and reach `https://FQDN` (public DNS/hairpin NAT).
* Missed pop-ups are always under the **bell** (Notification Log). Check *HC Settings > Enable Pop-up Notifications*
  and the step's *Also Show Pop-up*.

## Other common issues

| Symptom | Fix |
|---|---|
| `create-site` exits with *Access denied for user 'root'* | `DB_ROOT_PASSWORD` changed after the DB volume was created. Use the original password, or `docker compose down -v` (**deletes all data**) and start again. |
| Site opens the setup wizard | Normal on a new frappe-only site. Complete it or use the CLI command in README §4.3. The time zone is reset to Asia/Qatar afterwards. |
| `bench migrate` did not pick up a JSON change | Bump `"modified"` in the changed JSON file, then migrate again. |
| Teams step *Failed: HTTP 400* | The webhook URL is wrong or truncated (must be the full Workflows URL), or the flow expects a different payload. Use *HC Settings > Send Test Teams Card*. |
| Teams step *Failed: No Teams webhook URL configured* | Fill *HC Settings > Default Teams Webhook URL* or the step's *Teams Webhook URL*. |
| Steps never fire for a contract | Check the contract's **Notifications** tab: the reason is shown per step (status filter, no recipients, no scheduled date…). Use **Test Flow**. |
| Port 8080 already in use | Change `HTTP_PORT` in `.env` (and `HOST_NAME`), then `docker compose up -d`. |

## Device data collection (Phase 2)

The per-device error is on the **HC Collection Run > Devices** table and on the device row (*Last Error*). Raw output
is in the run's ZIP. Background errors are in **Error Log** ("HC Tracker: collection failed …").

| Error | Fix |
|---|---|
| `Connection timed out: TCP connection to device failed` | The container cannot reach the device. Test from the worker: `docker compose exec queue-long bash -c "wait-for-it -t 5 <ip>:22"`. Check routing/VPN/firewall from the Docker host. |
| `Authentication failed` | Wrong username/password, or SSH not allowed for that account (AAA/TACACS). Re-enter the password (Password fields show `*****`). |
| `Pattern not detected` / `read_timeout` (Netmiko) | Slow device or unusual prompt/banner. Raise *HC Settings > Device Timeout*. Check the platform is correct (e.g. a Catalyst 9800 must be *Cisco Catalyst 9800 WLC*, not AireOS). |
| `% Invalid input` in *command errors* (status Partial) | That command is not supported on this platform/version. Remove it from *Extra Commands*. The standard commands are listed in `collectors/platforms.py`. |
| `TLS error (untick Verify SSL …)` | The device uses a self-signed certificate. Untick *Verify SSL Certificate*, or install a trusted certificate. |
| `PAN-OS API error: Invalid Credential` / `403` | Check the API key, or the username/password used for keygen. The admin role needs *XML API > Operational Requests*. |
| `FortiOS API authentication failed (HTTP 401/403)` | Wrong token, or the HC Tracker server IP is not in the REST API admin's *Trusted Hosts*. |
| Run stays *Queued* | The `queue-long` worker is down. `docker compose ps queue-long`, `docker compose logs queue-long`. |
| "A collection is already running" | A previous run is Queued/Running. Wait, or if the worker died, set that run's status to Failed (System Manager, *Set Value*). |
| Button *Collect Device Data* missing | Only the assigned engineer, the account manager and Technical/System Managers see it, and at least one device must be enabled. |
| Draft PDF missing / `wkhtmltopdf` error | Check Error Log. The official image ships wkhtmltopdf. Re-run with *Run Again*. |
